# Сопоставление БД и Google Sheets

Документ описывает текущее поведение `pipeline/orchestrator/sync_sheets.py` и вызываемых им delivery-модулей. Анализ выполнен по коду; фактическое содержимое новой БД и Google Sheets не проверялось.

## 1. Общая схема

`run_all_sheets_sync()` последовательно запускает:

1. `sync_streams_safe()` — лист `STREAMS_SHEET_NAME`.
2. `sync_games_safe()` — лист `GAMES_SHEET_NAME`.
3. `sync_releases_safe()` — лист `RELEASES_SHEET_NAME`.
4. `sync_recommendations_safe()` — лист `RECOMMENDATIONS_SHEET_NAME`.

Все табличные данные записываются с 9-й строки. Перед записью сравнивается уже существующий диапазон данных с рассчитанными строками. Если строки отличаются, очищается диапазон до 1000-й строки и выполняется запись через `USER_ENTERED`; если отличаются только формулы/значения, определённые как ручные, это может быть учтено специальной логикой.

`sync_bot_info` импортирован в оркестраторе, но не вызывается. Поэтому лист бота текущим запуском `run_all_sheets_sync()` не синхронизируется.

## 2. Лист стримов

Источник строк: все записи `streams`, сортировка `started_at DESC`. Фильтра по активности, наличию игр или наличию записи VOD нет.

Каждая запись занимает строку `A9:L...`:

| Ячейка | Что записывается | Источник и преобразование | Условие |
|---|---|---|---|
| A | Дата и время начала | `streams.started_at`, формат `%d.%m.%Y\\n%H:%M` | `started_at` должен быть не `NULL`, иначе вызов `strftime` завершится ошибкой |
| B | Длительность в часах | `streams.duration_minutes / 60`, строка с максимумом одним десятичным знаком | Если `duration_minutes IS NULL`, записывается пусто |
| C | Название стрима | `streams.title` | `NULL` превращается в пустую строку |
| D | Игры стрима | связанные `stream_games` → `games.name`, соединение через ` -> ` | Игры берутся только если загружена связь `stream_games.game`; отсутствующие связанные игры пропускаются |
| E | Ссылка на Twitch VOD | первый `stream_recordings.url` для данного стрима, где `source = 'twitch'`; создаётся `HYPERLINK(...; "Twitch")` | Если подходящей записи нет, пусто. Если таких записей несколько, выбирается произвольная первая из-за `LIMIT 1` без сортировки |
| F | Ручное поле | При построении новой строки пусто | При совпадении ключа с существующей строкой сохраняется старое значение F |
| G | Ручное поле | При построении новой строки пусто | Сохраняется старое значение при совпадении ключа |
| H | Ручное поле | При построении новой строки пусто | Сохраняется старое значение при совпадении ключа |
| I | Ручное поле | При построении новой строки пусто | Сохраняется старое значение при совпадении ключа |
| J | Ручное поле | При построении новой строки пусто | Сохраняется старое значение при совпадении ключа |
| K | Теги стрима | Для существующего стрима сохраняется старое значение. Для нового стрима должна применяться логика тегов из раздела 2.1 ниже | Текущая реализация оставляет K пустой для нового стрима |
| L | Участники | `streamers_on_stream` → `users.display_name`, имена соединяются пробелом | Пустые `display_name` пропускаются |

Ключ для сохранения ручных F:K — пара `(отформатированный started_at, title)`. Если дата или название пустые, существующая строка не участвует в сопоставлении. Изменение названия или форматирования времени создаёт новую строку и может потерять ручные F:K.

### 2.1. Требуемая логика нового тега K

Для нового стрима значение K должно строиться так:

- если среди категорий стрима только `Just Chatting`, добавить `Общение`;
- если на стриме были игры/категории кроме `Just Chatting`, `Общение` не добавлять;
- для всех игр стрима получить жанры из `game_genres` → `genres`: использовать `abbreviation`, а при его отсутствии `name`; жанры объединить запятыми;
- если у стрима есть хотя бы один участник в `streamers_on_stream`, добавить `Кооп`;
- если в `streams.title` встречается `IRL` или среди игр стрима есть игра с названием `IRL`, добавить `IRL`;
- итоговые теги следует объединить в согласованном порядке и без дубликатов.

Для уже существующих строк K менять нельзя — значение нужно брать из текущей строки Sheets вместе с остальными сохранёнными полями. Сейчас `_build_stream_row()` возвращает пустое значение K, поэтому требуемая логика для новых стримов пока отсутствует.

## 3. Лист игр

По требованию должны попадать только игры, у которых есть связь со стримами через таблицу `stream_games` (в разговоре она может называться `games_stream`), и только игры, у которых существует запись `game_stats`. Текущий код вместо этого фильтрует по `games.is_active = TRUE`; в показанной модели `Game` такого поля нет. Если схема действительно не содержит этого столбца, текущий запрос требует исправления и может завершаться ошибкой. После сбора данных сначала вычисляется рейтинг по `streamed_hours` (убывание, затем имя), затем строки выводятся по `last_stream` (сначала непустые, от новых к старым, затем имя). Ранг остаётся рассчитанным по первой сортировке.

Каждая запись занимает строку `A9:L...`:

| Ячейка | Что записывается | Источник и преобразование | Условие |
|---|---|---|---|
| A | Последний стрим | `game_stats.last_stream`, формат `%Y-%m-%d` | Без `game_stats` игра исключается; `last_stream IS NULL` даёт пусто |
| B | Число стримов | `game_stats.streams_count`, `int(... or 0)` | При `NULL` — 0 |
| C | Название игры | `games.name` | В нормальной схеме `NOT NULL`; используется как ключ существующей строки |
| D | Ранг по часам | Порядковый номер после сортировки по `streamed_hours DESC`, имя | Рассчитывается только среди игр, прошедших фильтры |
| E | Часы на стримах | `game_stats.streamed_hours` | При `NULL` — 0 |
| F | Время прохождения | `game_metadata_hltb.hltb_all_styles` | При отсутствии HLTB-метаданных или значения — пусто |
| G | Steam | `game_metadata_igdb.steam_url`, формула `HYPERLINK(...; "Steam")` | При отсутствии IGDB-метаданных или URL — пусто |
| H | Лайк | `streamer_games.liked` для стримера `users.id = 45` (`login = tabula`) | При отсутствии связи/значения — `False`; агрегирование по всем стримерам не требуется |
| I | Иконка лайка | Формула `=IF(H<номер строки>=TRUE;"♥";"")` | Рассчитывается Sheets; формула ставится для каждой фактической строки |
| J | Пройдено | `bool_or(streamer_games.completed)` по всем стримерам для игры | При отсутствии/только `NULL` значение превращается в `False` |
| K | Иконка прохождения | Формула `=IF(J<номер строки>=TRUE;"✅";"")` | Рассчитывается Sheets |
| L | Теги | платформы и жанры, объединённые через ` | ` | Для каждой связи берётся `abbreviation`, иначе `name`; пустые группы пропускаются |

Отдельно важный цикл: перед чтением игр листовые H и J записываются обратно в БД в `streamer_games` для стримера `users.id = 45` (`login = tabula`). Значение H должно читаться из этой же связи, а не агрегироваться по всем стримерам. В текущем коде и чтение, и запись используют жёстко заданный `streamer_id = 1`, а чтение H/J выполняется через `bool_or` по всем стримерам. Это нужно изменить.

При сопоставлении с листом ключом является точное `games.name`. Ручные значения I и K сохраняются как существующие значения при перестановке, но затем формулы I/K всё равно перегенерируются. При удалении игры из выборки её строка исчезает после очистки `A9:L1000`.

## 4. Лист релизов

Перед выборкой вызывается `refresh_recommendation_lifecycle()`. Сейчас функция возвращает 0 и не меняет БД, но это скрытая точка расширения и её поведение стоит учитывать при будущих изменениях.

В выборку попадают игры, для которых одновременно выполняется:

- есть запись в `game_metadata_igdb`;
- есть хотя бы одна запись в `game_recommendations`;
- `release_date > datetime.utcnow()` или `release_date IS NULL`.

Сортировка: сначала известные даты по возрастанию, затем игры с неизвестной датой, внутри — `games.name ASC`.

Каждая запись занимает строку `A9:L...`:

| Ячейка | Что записывается | Источник и преобразование | Условие |
|---|---|---|---|
| A | Дата релиза | `game_metadata_igdb.release_date`, `%d.%m.%Y\\n%H:%M` | При `NULL` — пусто; для попадания в выборку `NULL` допустим |
| B | Сколько дней до релиза | Разница даты релиза с `datetime.utcnow().date()` | Для неизвестной даты — пусто; прошедшая дата — пусто; сегодня — текст «сегодня»; иначе число дней |
| C | Название | `games.name` | Нужна запись рекомендации; используется как ключ существующей строки |
| D | Русское описание | `game_metadata_igdb.description_ru` | При отсутствии метаданных/описания — пусто |
| E | Steam | `game_metadata_igdb.steam_url` в формуле `HYPERLINK` | При отсутствии URL — пусто |
| F | Интерес стримера | `streamer_games.interested` для `streamer_id = 1` | При отсутствии связи/значения — `FALSE` |
| G | Иконка интереса | Формула `=IF(F<номер строки>=TRUE;"👍";"")` | Формула пересчитывается Sheets |
| H | Ручное поле | Пусто в новой строке | В текущей функции значение не сохраняется отдельно: при построении строки G:J заменяются содержимым старой строки |
| I | Ручное поле | Пусто в новой строке | То же |
| J | Ручное поле | Пусто в новой строке | То же |
| K | Теги | платформы и жанры через ` | ` | `abbreviation`, иначе полное имя; при отсутствии — пусто |
| L | Кто рекомендовал | `game_recommendations` → `users.login/display_name` | Специальные login `tabula` и `igdb` превращаются в фиксированные подписи; остальные берутся по `display_name` |

Перед выборкой F из существующего листа синхронизируется обратно в БД. При `TRUE` выставляется `streamer_games.interested = TRUE` для `streamer_id = 1`. При `FALSE` значение выставляется только если текущая запись уже равна `FALSE`; если текущая запись `TRUE`, код её не сбрасывает. Это асимметричное поведение может быть неожиданным.

## 5. Лист рекомендаций

Перед выборкой также вызывается `refresh_recommendation_lifecycle()`.

В выборку попадают игры, для которых одновременно выполняется:

- есть хотя бы одна запись `game_recommendations`;
- есть запись `game_metadata_igdb`;
- `release_date IS NOT NULL`;
- `release_date <= datetime.utcnow()`.

То есть это список рекомендованных игр с уже наступившей датой релиза. Наличие `games.is_active` и наличие стрима здесь не проверяются.

Каждая запись занимает строку `A9:I...`:

| Ячейка | Что записывается | Источник и преобразование | Условие |
|---|---|---|---|
| A | Дата релиза | `game_metadata_igdb.release_date`, `%d.%m.%Y` | Игра попадает в выборку только при непустой дате |
| B | Число голосов | `COUNT(game_recommendations.game_id)` | Минимум одна рекомендация, иначе игра не попадает |
| C | Название | `games.name` | Используется напрямую |
| D | Steam | `game_metadata_igdb.steam_url` в формуле `HYPERLINK` | При отсутствии URL — пусто |
| E | Оценка IGDB | `game_metadata_igdb.igdb_score`, обработка `format_rating_value` | Берётся часть до первого `|`; для числового значения это может привести к ошибке, если тип реально не строковый |
| F | Теги | платформы и жанры через ` | ` | `abbreviation`, иначе полное имя |
| G | Ручное поле | Пусто | Не заполняется из БД |
| H | Ручное поле | Пусто | Не заполняется из БД |
| I | Кто рекомендовал | связи `game_recommendations` → `users`, с особыми подписями для `tabula`/`igdb` | При отсутствии корректного `display_name` отдельный рекомендатель не выводится |

Сортировка: `release_date ASC`, затем `games.name ASC`. При изменении строк лист очищается `A9:I1000`.

## 6. Лист информации о боте

Функция `sync_bot_info()` не читает БД. Она читает `docs/CHAT_COMMANDS.txt` и записывает весь текст в `A1` листа `BOT_INFO_SHEET_NAME`, если текст отличается от текущего значения `A1`. Но поскольку функция не включена в `run_all_sheets_sync`, при запуске указанного оркестратора `A1` не обновляется.

## 7. Что проверить в новой БД до запуска

1. Подключение `AsyncSessionLocal` действительно указывает на новую БД.
2. Присутствуют таблицы и связи: `games`, `game_stats`, `game_metadata_igdb`, `game_metadata_hltb`, `streams`, `stream_games`, `stream_recordings`, `users`, `streamers_on_stream`, `streamer_games`, `game_recommendations`, `game_genres`, `game_platforms`, `genres`, `platforms`.
3. Есть пользователь с `users.id = 45`, `login = tabula`, и это действительно нужный стример. Код использует этот ID через настройку `SHEETS_STREAMER_ID` (по умолчанию 45).
4. Для активных игр, которые должны попасть на лист игр, есть `game_stats`.
5. Для релизов и рекомендаций заполнена `game_metadata_igdb`; без неё игра полностью исключается из обоих этих листов.
6. В `game_recommendations` корректно сохранены связи с пользователями. Одна игра должна иметь хотя бы одну такую связь, чтобы попасть в релизы/рекомендации.
7. В `stream_games` присутствуют корректные `game_id`, а у `Stream.stream_games` загружается связанная игра.
8. Даты находятся в одной временной зоне с ожиданиями кода: используется смесь `datetime.utcnow()` и сравнение с датами из БД.
9. В Google Sheets строки данных начинаются с 9-й строки, а существующие ручные значения расположены именно в описанных колонках.
10. У Google-аккаунта/сервисного аккаунта есть доступ к таблице с именем `Tabula Streams`.

## 8. Найденные вопросы и предложения

- Подтверждено: нужный стример — `users.id = 45`, `login = tabula`. Все обращения к `streamer_games` для листов игр и релизов нужно перевести с жёсткого `streamer_id = 1` на ID 45 либо, надёжнее, на поиск пользователя по login/настройке.
- Для листа стримов требуется реализовать вычисление K для новых строк; существующие K сохранять без изменений.
- Фильтр листа игр нужно заменить с `Game.is_active == True` на наличие связи игры со `stream_games`.
- В листе игр H нужно получать как `streamer_games.liked` именно для `streamer_id = 45`, без `bool_or` по всем стримерам.
- Нужно решить, должен ли `sync_bot_info()` входить в общий запуск. Сейчас импорт создаёт впечатление, что должен, но фактически он не вызывается.
- Стоит добавить диагностический режим перед записью: количество строк по каждому листу и количество игр, отсеянных каждой причиной (нет `game_stats`, нет IGDB, нет рекомендаций и т. п.). Это сильно упростит проверку миграции.
- Для миграции безопаснее сначала сделать копию Google Sheets: safe-синхронизация может очистить диапазоны и убрать строки, которые не проходят новые условия.
- Следует отдельно проверить кодировку исходников/строк с русским текстом и emoji: в некоторых прочитанных файлах видны признаки mojibake. Это может повлиять на подписи, формулы и сравнение строк в Sheets.

Основные места реализации: `pipeline/orchestrator/sync_sheets.py`, `pipeline/delivery/sheets_streams.py`, `pipeline/delivery/sheets_games.py`, `pipeline/delivery/sheets_releases.py`, `pipeline/delivery/sheets_recommendations.py`, `pipeline/delivery/sheets_bot_info.py`.
