## 5. Потенциальные проблемы и ошибки

### Критические

| Проблема | Описание | Решение |
|----------|----------|---------|
| **`datetime.utcnow()`** | Используется в `recommendations_service.py:225,236` — deprecated в Python 3.12+, может работать иначе | Заменить на `datetime.now(timezone.utc)` |
| **SQLite vs PostgreSQL типы** | `String` в SQLite — любой тип, в PostgreSQL — varchar/text. `Boolean` в SQLite — 0/1, в PostgreSQL — true/false | SQLAlchemy абстрагирует, но проверить все default-значения |
| **`generated` колонки** | `duration_minutes` и `stream_games.duration_minutes` — в PostgreSQL это GENERATED ALWAYS AS, требует миграционный SQL | Использовать `Computed()` в SQLAlchemy или property |
| **`text` vs `String`** | В DBML `text` ≠ `String(255)`. В PostgreSQL `text` и `varchar` — почти одинаково, но надо проверить индексы | Использовать `Text()` для длинных полей |
| **UUID PK** | `web_sessions.id` — UUID. SQLite не поддерживает нативный UUID | В PostgreSQL использовать `Uuid` тип |
| **`json` тип** | `game_metadata_igdb.raw_payload` — `json`. SQLite хранит как text | В PostgreSQL использовать `JSONB` |
| **`smallint`** | `calendar_days.day`, `month`, `day_of_year` — `smallint`. SQLAlchemy маппинг через `SmallInteger` | Проверить совместимость |
| **`bigint` PK** | Многие таблицы используют `bigint` PK. SQLite — это всегда integer | В PostgreSQL `BIGINT` |
| **`float` vs `numeric`** | `float` в DBML — PostgreSQL `real`/`double precision`. Для денег/точных значений лучше `Numeric` | Проверить, где нужна точность |
| **Нет Alembic** | Текущие миграции — ad-hoc скрипты. PostgreSQL требует нормальную миграционную систему | Установить Alembic |

### Средние

| Проблема | Описание |
|----------|----------|
| **Маппинг `participants` → `users`** | `participants` — простые участники (name, display_name). `users` — полноценные Twitch-пользователи. Данные могут не перенестись без потерь |
| **`recommended_games` → `game_recommendations`** | Полностью другая модель. Текущие рекомендации с голосами невозможно напрямую перенести — нужна конвертация |
| **`games_meta` → 3 таблицы** | Текущие `liked`, `completed` идут в `streamer_games`, `hltb_hours` → `game_metadata_hltb`, `steam_url` → `game_metadata_igdb`. Нужно определить `streamer_id` для `streamer_games` |
| **Потеря `period` в `game_stats`** | Текущая таблица поддерживает несколько периодов (`all`, `month`, etc.). Целевая — только один набор статистики |
| **`game_aliases`** | Текущие `games.name` должны стать алиасами. Нужно decide: что является primary alias? |
| **Нет `stream_participants` в целевой** | Заменяется на `streamers_on_stream`, но с другим смыслом: участники vs стримеры на стриме |

### Низкие

| Проблема | Описание |
|----------|----------|
| **Синхронная vs асинхронная** | Текущий код использует синхронный SQLAlchemy. PostgreSQL лучше работает с async (asyncpg). Не критично, но стоит рассмотреть |
| **`casefold()` в коде** | PostgreSQL по умолчанию case-sensitive. Если где-то используется `LIKE` без `ILIKE`, будут проблемы с поиском |
| **`datetime` timezone** | SQLite не хранит timezone. PostgreSQL — `TIMESTAMP` или `TIMESTAMPTZ`. Надо выбрать и быть консистентным |
| **`ON DELETE CASCADE`** | Текущие ForeignKey в целевой схеме не указывают `ON DELETE`. SQLite не поддерживает FK по умолчанию. PostgreSQL — поддерживает, но нужно явно указать каскады |
| **Индексы** | Текущие индексы определены в DBML, но в SQLAlchemy нужно будет объявить их явно через `Index()` |
| **`storage/streams.db`** | Файл будет не нужен. Нужно обновить `.gitignore`, `Dockerfile`, `docker-compose.yml` |
